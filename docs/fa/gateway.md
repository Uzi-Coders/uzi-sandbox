# مستندات API درگاه پرداخت (سندباکس)

یک درگاه پرداخت آزمایشی برای توسعه و تست. روند کار و قالب پاسخ‌های آن شبیه سرویس پرداخت [آیدی‌پی (IDPay)](https://idpay.ir) است، بنابراین کدی که برای این سندباکس نوشته می‌شود به‌راحتی با یک درگاه واقعی سازگار می‌شود. این پروژه **هیچ ارتباطی با آیدی‌پی ندارد** و **هیچ پولی جابه‌جا نمی‌شود**.

- **مسیر پایه:** `/sandbox/gateway`
- **فرمت:** درخواست و پاسخ به‌صورت JSON (به‌جز صفحه پرداخت آزمایشی که یک فرم HTML است)
- **واحد مبلغ:** ریال
- **نکته:** پیام‌های خطا به زبان فارسی برگردانده می‌شوند.

## روند کار

1. سرور شما **ایجاد تراکنش** را فراخوانی می‌کند و یک `id` و یک `link` پرداخت دریافت می‌کند.
2. کاربر را به `link` هدایت کنید. در صفحه پرداخت آزمایشی می‌تواند پرداخت را تأیید یا لغو کند.
3. کاربر به آدرس `callback` شما بازگردانده می‌شود و نتیجه در query string ارسال می‌شود.
4. سرور شما **تأیید پرداخت** را فراخوانی می‌کند تا پرداخت نهایی شود.

## احراز هویت

مسیرهای API (`/payment` و `/payment/verify`) باید کلید API حساب شما را در هدر `X-API-Key` داشته باشند.

```
X-API-Key: <your-api-key>
```

| وضعیت | توضیح                                  |
|-------|----------------------------------------|
| 401   | هدر ارسال نشده یا کلید API نامعتبر است |

## وضعیت‌های تراکنش

| وضعیت | توضیح                       |
|-------|-----------------------------|
| `1`   | ایجاد شده، در انتظار پرداخت |
| `2`   | پرداخت ناموفق یا لغو شده    |
| `10`  | پرداخت شده، در انتظار تأیید |
| `100` | پرداخت شده و تأیید شده      |

## ایجاد تراکنش

`POST /sandbox/gateway/payment`

### بدنه درخواست

| فیلد       | نوع      | اجباری | توضیح                                                                                                          |
|------------|----------|--------|----------------------------------------------------------------------------------------------------------------|
| `order_id` | رشته     | بله    | شناسه سفارش در سیستم شما                                                                                       |
| `amount`   | عدد صحیح | بله    | مبلغ به ریال، از `1000` تا `500000000`                                                                         |
| `callback` | رشته     | بله    | آدرس بازگشت، باید با `http://` یا `https://` شروع شود                                                          |
| `name`     | رشته     | خیر    | نام پرداخت‌کننده                                                                                               |
| `phone`    | رشته     | خیر    | شماره موبایل پرداخت‌کننده (`09xxxxxxxxx`، `+989xxxxxxxxx` یا `9xxxxxxxxx`؛ به‌صورت `09xxxxxxxxx` ذخیره می‌شود) |
| `mail`     | رشته     | خیر    | ایمیل پرداخت‌کننده                                                                                             |
| `desc`     | رشته     | خیر    | توضیحات                                                                                                        |

### نمونه درخواست

```bash
curl -X POST https://example.com/sandbox/gateway/payment \
  -H "X-API-Key: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "order_id": "1001",
    "amount": 50000,
    "callback": "https://your-site.com/payment/callback",
    "name": "علی",
    "phone": "09123456789",
    "mail": "ali@example.com",
    "desc": "سفارش آزمایشی"
  }'
```

### پاسخ موفق (201)

```json
{
  "id": "3f2b8c1e9a7d4e5f8b6a0c9d1e2f3a4b",
  "link": "https://example.com/sandbox/gateway/fake-pay/3f2b8c1e9a7d4e5f8b6a0c9d1e2f3a4b"
}
```

### خطاها

| وضعیت | علت                                                     |
|-------|---------------------------------------------------------|
| 400   | بدنه درخواست JSON معتبر نیست یا خالی است                |
| 400   | یکی از فیلدهای اجباری ارسال نشده یا خالی است            |
| 400   | نوع یکی از فیلدها نادرست است                            |
| 400   | `amount` کمتر از ۱٬۰۰۰ یا بیشتر از ۵۰۰٬۰۰۰٬۰۰۰ ریال است |
| 400   | `callback` یک آدرس معتبر HTTP/HTTPS نیست                |
| 400   | فرمت `mail` نامعتبر است                                 |
| 401   | کلید API ارسال نشده یا نامعتبر است                      |
| 411   | فرمت `phone` نامعتبر است                                |

## صفحه پرداخت آزمایشی

`GET /sandbox/gateway/fake-pay/<id>`

صفحه‌ای که در آن کاربر می‌تواند پرداخت را تأیید یا لغو کند. این صفحه فقط تا زمانی که وضعیت تراکنش `1` است در دسترس است و در غیر این صورت خطای 404 برمی‌گرداند.

با ارسال فرم صفحه (`POST` با فیلد `action`)، کاربر به `callback` شما هدایت می‌شود:

### تأیید پرداخت (`action=confirm`)

وضعیت تراکنش `10` می‌شود، یک `track_id` پنج‌رقمی تصادفی و یک شماره کارت آزمایشی ساخته می‌شود و کاربر به این آدرس هدایت می‌شود:

```
<callback>?status=10&track_id=12345&id=<id>&order_id=<order_id>&amount=<amount>&card_no=123456******7890
```

### لغو پرداخت (هر مقدار دیگر برای `action`)

وضعیت تراکنش `2` می‌شود و کاربر به این آدرس هدایت می‌شود:

```
<callback>?status=2&id=<id>&order_id=<order_id>
```

> پارامترها با `?` به انتهای آدرس اضافه می‌شوند؛ بنابراین برای `callback` آدرسی بدون query string استفاده کنید.

## تأیید پرداخت

`POST /sandbox/gateway/payment/verify`

پس از بازگشت کاربر، این مسیر را از سمت سرور خود فراخوانی کنید. فقط تراکنش‌های با وضعیت `10` قابل تأیید هستند و هر تراکنش فقط یک‌بار تأیید می‌شود.

### بدنه درخواست

| فیلد       | نوع  | اجباری | توضیح                                                     |
|------------|------|--------|-----------------------------------------------------------|
| `id`       | رشته | بله    | شناسه تراکنش (`id`) که هنگام ایجاد تراکنش دریافت کرده‌اید |
| `order_id` | رشته | بله    | همان `order_id` که هنگام ایجاد تراکنش ارسال کرده‌اید      |

### نمونه درخواست

```bash
curl -X POST https://example.com/sandbox/gateway/payment/verify \
  -H "X-API-Key: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"id": "3f2b8c1e9a7d4e5f8b6a0c9d1e2f3a4b", "order_id": "1001"}'
```

### پاسخ موفق (200)

```json
{
  "status": "100",
  "track_id": "12345",
  "id": "3f2b8c1e9a7d4e5f8b6a0c9d1e2f3a4b",
  "order_id": "1001",
  "amount": "50000",
  "date": "1767225600",
  "payment": {
    "track_id": "12345",
    "amount": "50000",
    "card_no": "123456******7890",
    "hashed_card_no": "9F86D081884C7D659A2FEAA0C55AD015A3BF4F1B2B0B822CD15D6C15B0F00A08",
    "date": "1767225700"
  },
  "verify": {
    "date": "1767225800"
  }
}
```

همه تاریخ‌ها به‌صورت Unix timestamp (ثانیه) هستند. مقدار `hashed_card_no` هش SHA-256 (با حروف بزرگ) شماره کامل کارت آزمایشی است.

### خطاها

| HTTP | `error_code` | علت                                                                  |
|------|--------------|----------------------------------------------------------------------|
| 400  | –            | بدنه درخواست JSON معتبر نیست یا خالی است                             |
| 401  | –            | کلید API ارسال نشده یا نامعتبر است                                   |
| 406  | 31           | `id` یا `order_id` ارسال نشده، خالی یا از نوع رشته نیست              |
| 400  | 52           | تراکنشی با این `id` و `order_id` پیدا نشد                            |
| 405  | 53           | تأیید تراکنش ممکن نیست (پرداخت نشده، لغو شده یا قبلاً تأیید شده است) |

نمونه بدنه خطا:

```json
{
  "error_code": 53,
  "error_message": "تایید پرداخت امکان پذیر نیست."
}
```

## پنل وب

`GET /sandbox/gateway/panel` (نیازمند ورود)

تراکنش‌های کاربر واردشده را از جدیدترین به قدیمی‌ترین و با ۱۰ مورد در هر صفحه نمایش می‌دهد. برای صفحه‌بندی از `?page=N` استفاده کنید.

ورود از آدرس `/sandbox/auth/login` انجام می‌شود. حساب کاربری با دستور `python register_user.py` در خط فرمان ساخته می‌شود.
